# Spec-kit 초기 명세 추천 5가지

안녕하세요! "익명 고민 상담 게시판" 프로젝트를 spec-kit으로 시작할 때, 가장 먼저 명세화하면 좋은 5가지 핵심 주제를 추천해 드립니다. 이들을 먼저 정의하면 프로젝트의 기술적 토대를 명확히 하고, 이후 개발 과정을 원활하게 진행할 수 있습니다.

---

### 1. 사용자 식별 및 세션 관리 명세 (User Identification & Session Specification)

**이유:** "완전 익명"은 우리 프로젝트의 가장 중요한 원칙입니다. 로그인 없이 사용자를 구분하는 메커니즘은 모든 기능의 기반이 되므로, 가장 먼저 명확하게 정의해야 합니다.

**명세에 포함할 내용:**
- 사용자 식별자(UUID 등)의 생성 및 저장 방식 (LocalStorage vs. Cookie)
- 식별자의 유효 기간 및 갱신 정책
- 서버에서 식별자를 처리하고 유저를 구분하는 방법

### 2. 게시글 및 댓글 서비스 명세 (Post & Comment Service Specification)

**이유:** 사용자의 핵심 활동인 '글쓰기'와 '댓글 달기' 기능의 데이터 모델과 API를 정의합니다. 이는 프로젝트의 중심 기능입니다.

**명세에 포함할 내용:**
- `Post`와 `Comment`의 데이터 모델 (필드: 제목, 내용, 작성자 식별자, 생성 시간 등)
- 게시글/댓글의 CRUD(생성, 조회, 수정, 삭제)를 위한 API 엔드포인트 정의
- 좋아요(Like) 기능의 데이터 처리 방식 및 API 명세

### 3. 콘텐츠 필터링 (욕설 필터) 명세 (Content Moderation Specification)

**이유:** "정서적으로 안정적인 UX"를 제공하고 커뮤니티의 건강성을 유지하기 위한 필수 기능입니다. 필터링 정책과 기술적 구현을 초기에 정의해야 합니다.

**명세에 포함할 내용:**
- 필터링 대상: 게시글 제목, 내용, 댓글
- 필터링 방식: 자체 단어 목록(Blocklist) 사용 여부, 외부 API 연동 여부
- 욕설 감지 시 처리 정책 (등록 거부 vs. 자동 마스킹 처리)

### 4. '내 활동' 조회 명세 (My Activity Specification)

**이유:** PRD에 명시된 핵심 기능으로, 사용자가 자신의 콘텐츠를 관리할 수 있게 해줍니다. 익명 환경에서 '내 글'과 '내 댓글'을 어떻게 추적하고 보여줄지 명확한 정의가 필요합니다.

**명세에 포함할 내용:**
- 브라우저 식별자를 기반으로 자신이 작성한 게시글/댓글 목록을 조회하는 API
- 목록에 표시될 정보 (제목, 작성 시간, 좋아요 수 등)
- 해당 화면에서의 콘텐츠 삭제 기능 흐름

### 5. 검색 API 명세 (Search API Specification)

**이유:** 사용자가 원하는 정보를 쉽게 찾을 수 있도록 돕는 핵심 기능 중 하나입니다. 어떤 데이터를 어떻게 검색할지 미리 정의해야 효율적인 데이터베이스 설계가 가능합니다.

**명세에 포함할 내용:**
- 검색 대상 필드 (게시글 제목, 내용 등)
- 검색 API의 요청(Request) 및 응답(Response) 형식
- 검색 결과의 정렬 기준 (최신순, 관련도순 등)
